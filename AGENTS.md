# Budgetism: Read-first development rules

1. Before any changes, read this file, DEVELOPMENT_HANDOFF.md, and docs/IMPLEMENTATION_STATUS.md. Inspect current GitHub default branch, active branches, PRs, latest releases and workflows. Prefer newer verified repository work over this source ZIP.
2. Repository: https://github.com/TechSavage1989/budgetism. On October 27, 2026, it was public with a placeholder README, one initial commit, and no releases. No publication rights should be inferred from repo visibility or this source archive.
3. Version baseline: 0.1.0-dev.1 for newly named Budgetism. Source only; not a verified native application release. Inherited Private Finance code was 0.1.0-dev.1, uncompiled and unpublished.
4. Product: private personal finance; Windows first, Flutter client for multiple platforms, .NET 10 API, PostgreSQL, and eventual encrypted native offline database. Do not change architecture or financial data ownership without approval.
5. Current explicit exclusion: **No server setup, Codex CLI automation, unattended workers, payment setup or API-account setup.** API source exists from prior work, but its deployment and configuration must not be added in this scope.
6. Never put real financial records or credentials in demo fixtures, screenshots, logs, test output, source, or generated release files. Demo is ephemeral, labelled, and uses invented entries only.
7. Exact integer minor-unit financial amounts and balanced double-entry postings are mandatory. A transfer/card payment must not be counted twice. Mutation IDs must be unique and idempotent. Build migrations, encrypted storage and backup verification before production use.
8. Update feed: public GitHub releases, Windows filename Budgetism.exe and Windows ZIP filename Budgetism-Windows-x64.zip. Checks at startup, every five minutes while active, and on focus return after two minutes. Respect ETags, single-flight, rate limits and retry windows. Don't call offline/unknown status 'up to date'.
9. Never install untrusted ZIPs, unverified hashes, wrong app identity/version/architecture or extra executables. SHA-256 is not publisher signing. Manual Download/Install, health-checked relaunch, only one persistent rollback. Install remains disabled until real native Windows tests pass.
10. Keep logs/cache/downloads/preferences per-user, never persist them next to Budgetism.exe. Preserve stable shortcut/executable targets and custom filename behavior. Future migrations must be explicit and tested.
11. The allowed tracked root FILES are README.md, AGENTS.md, DEVELOPMENT_HANDOFF.md, and .gitignore. Source subdirectories: apps/, services/, tools/, tests/, scripts/, docs/, assets/, and .github/. If a new required manifest belongs at root, review and add it to the root guard explicitly.
12. Run `python scripts/check_layout.py --self-test` and `python scripts/check_layout.py` with or without .git; they must detect unexpected root entries. Don't accumulate build artifacts in tracked root.
13. Code checks: Go unit tests including negative controls, Windows cross-compile; Flutter analyze/test/web/windows; .NET backend build and ledger tests; runtime native Windows updater tests; ZIP extraction and verification; README link/anchor checks. Report omitted tests precisely.
14. Before any authorized repo push, recheck main branch SHA, branches, PRs and concurrent edits. Never force push or rewrite shared history. Never publish public source, release, tags or access changes without explicit authorization.
15. Documentation: centered one-H1 README, short centered tagline, navigation row, exact current functionality. Keep this file and DEVELOPMENT_HANDOFF.md current. Release notes in docs/releases/, not tracked root.
